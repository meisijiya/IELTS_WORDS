一行触发 deploy

默认入口：往 main 分支 push 一次，CI 通过后自动进入 deploy job。 整个过程 5 到 6 分钟。 

git add .
git commit -m "feat: ..."
git push origin main

跑完后到 https://github.com/<owner>/<repo>/actions 看 run 状态： 绿勾 = 服务已是新版本；红 X = 进入下一节排查。

手动触发 workflow

不想 commit 也能 deploy：到 GitHub → Actions → Build & Deploy → 右上角 Run workflow → 选 main 分支。

适用场景：仅修改 server 上的脚本或 ops workflow（无需触发 build）；线上事故热修后想 重新跑一遍以确认 build 没问题。

重跑失败的 run

GitHub Actions → 失败的 run → 右上角 Re-run jobs。 想清空旧 cache 重建选 Re-run jobs 时勾 Force rebuild without cache。

什么时候必须 force rebuild：改过 AUDIO_BUNDLE_URL、 Dockerfile 的 ARG、package-lock.json 又怀疑上次 cache 把陈旧 layer 复用过来时。

回滚到上一个正常版本

ACR 保留所有 :short_sha tag，rollback 很简单： 

ssh ubuntu@<host>
cd /opt/yasi-words

# 找一个 known-good 的 sha
export APP_IMAGE="$ALIYUN_REGISTRY/meisijiya/yasi-words:<old-sha>"
docker pull "$APP_IMAGE"
docker compose up -d --force-recreate app

server 端 prune 脚本默认保留当前 running image + 1 个最近非 running image， 所以 server 磁盘上一直有上一个版本可供回滚。如果想回滚到更早版本，从 docker images 里挑 sha，或去 ACR 控制台找历史 tag。
