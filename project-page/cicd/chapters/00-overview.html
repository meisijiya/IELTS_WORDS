系统图怎么读

本章不复制 SVG。请先打开 教材目录中的完整链路，再结合项目首页的 部署图示入口阅读。原始字符图与节点说明来自 CICD.md §0。

图的水平轴表示服务边界：GitHub 托管 runner、阿里云容器镜像服务 ACR、云服务器。 垂直轴表示时间顺序：提交代码、构建镜像、推送镜像、远程部署、浏览器访问。

五个关键节点

节点 职责 主要产物
本地开发环境 提交代码并执行 git push origin main Git commit
GitHub 触发 .github/workflows/deploy.yml Actions run
GitHub runner 执行 BuildKit 构建并推送三个镜像 tag 容器镜像
阿里云 ACR 保存 :latest、commit SHA 与时间戳 tag 可拉取的镜像版本
云服务器 拉取镜像并运行 Next.js 与 PostgreSQL 容器 可访问服务与持久化数据

数据流叙事

第一段：源码进入流水线

开发者把 main 分支推到 GitHub。GitHub 根据 workflow 的 push 触发器创建一次 run，使用 ubuntu-latest runner 拉取源码。此时流动的是 Git 对象与 workflow 配置。

第二段：源码变成镜像

build-and-push job 登录阿里云容器镜像服务 ACR，执行 docker/build-push-action@v6。Dockerfile、应用源码和构建参数被封装为不可变镜像层， 然后以 :latest、短 SHA、时间戳三个 tag 推送。此时流动的是镜像 manifest 与 layer。

第三段：镜像进入运行环境

只有构建成功后，deploy job 才会启动。它通过 appleboy/ssh-action@v1 连接服务器，导出 APP_IMAGE，执行 docker pull 与 docker compose up -d --force-recreate app。 此时流动的是 ACR 中的镜像内容，不是在服务器上重新编译的源码。

第四段：请求与数据分离

浏览器请求到达 Next.js 容器，业务数据写入 PostgreSQL。应用镜像可以随部署替换，数据库数据仍保存在 volume 中。 这就是为什么应用回滚与数据库变更必须分别考虑。

边界与持久化

记住一条主线：GitHub 负责自动化，ACR 负责镜像分发，云服务器负责运行，PostgreSQL volume 负责持久化。
  • GitHub Secrets 只向 workflow 提供部署凭证，不应写入仓库。
  • ACR 访问凭证与阿里云登录密码不是同一组凭证。
  • audio_data 与 PostgreSQL volume 的生命周期独立于应用容器。
  • 服务器上的 .env 保存运行时配置，不进入 Git。
