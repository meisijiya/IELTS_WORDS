最后更新 2026-07-25

本章内容

  • 按症状定位

出问题先复制对应行到本机或 server shell 跑。本章命令直接来自 CICD.md §5。

按症状定位

症状 第一步 第二步
deploy 步骤红了 gh run list --limit 5 gh run view <id> --log
server 代码没变 看 GH Actions log 里 build tag ssh ubuntu@<host> "docker images | grep yasi"
app 启动 500 docker compose logs --tail 50 app 看 entrypoint 报 schema / audio / seed
页面打不开 本机 curl 测 3000 端口 看 nginx 反代 + 安全组
audio 全部 404 进容器 ls /app/public/audio | wc -l 查 entrypoint 拉 audio 日志
DB 连不上 docker compose ps 看 postgres pg_isready 测连通性
磁盘满 df -h / 跑 Free-Disk workflow

一条命令速查

GitHub Actions / CLI

# 看 workflow 最近状态
gh run list --limit 5

# 看单次 run 详细日志
gh run view <id> --log

# 强制 clean rebuild（绕过 cache）
# GitHub Actions run page → Re-run jobs → 勾「Force rebuild without cache」

Server 状态

# 看 server 上镜像（确认 deploy 拉了新 image）
ssh ubuntu@<host> "docker images | grep yasi"

# 看 server 容器状态
ssh ubuntu@<host> "cd /opt/yasi-words && docker compose ps"

# 看 entrypoint / app 日志
ssh ubuntu@<host> "cd /opt/yasi-words && docker compose logs --tail 50 app"

# 本机直接测 3000 端口
ssh ubuntu@<host> "curl -sS -o /dev/null -w '%{http_code}\n' http://localhost:3000/login"

手动重现 deploy（绕过 CI/CD）

ssh ubuntu@<host> "cd /opt/yasi-words && \
  export APP_IMAGE=ACR_REGISTRY/meisijiya/yasi-words:latest && \
  docker pull \$APP_IMAGE && \
  docker compose pull app && \
  docker compose up -d --force-recreate app"
注意：上面 inline 示例里的 ACR_REGISTRY 占位符要替换成实际的 $ALIYUN_REGISTRY，例如 crpi-***.cn-shenzhen.personal.cr.aliyuncs.com。

ACR 镜像列表

# 用 aliyun CLI
aliyun cr ListRepositoryTag --RegionId cn-shenzhen \
  --Namespace meisijiya --RepositoryName yasi-words
