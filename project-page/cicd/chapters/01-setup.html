创建阿里云容器镜像服务 ACR

在阿里云容器镜像服务 ACR 个人版创建仓库，仓库名使用 yasi-words， 地域选择靠近服务器的区域。部署需要公网地址，例如 crpi-***.cn-shenzhen.personal.cr.aliyuncs.com。来源：§1.1。

字段建议值
仓库名yasi-words
地域cn-shenzhen、cn-hangzhou 或 cn-beijing
类型公开或私有，push 前都需要正确登录
代码源GitHub，可选，仅用于展示
凭证不要混用：ACR 用户名是访问凭证中的账号全名，ACR 密码需要单独设置。它们不是阿里云控制台登录密码。

配置 7 个 GitHub Secrets

进入 https://github.com/<owner>/<repo>/settings/secrets/actions， 逐项创建以下 repository secrets。来源：§1.2。

Secret内容错配症状
ALIYUN_REGISTRYcrpi-***.cn-shenzhen.personal.cr.aliyuncs.compush 或 pull 返回 401
ALIYUN_REGISTRY_NAMESPACEACR namespace镜像路径不存在
ALIYUN_REGISTRY_USERNAMEACR 访问凭证用户名docker login 返回 401
ALIYUN_REGISTRY_PASSWORDACR 独立密码docker login 返回 401
DEPLOY_HOST<host>SSH 连接失败
DEPLOY_SSH_USERubuntu 或 root用户不匹配导致 Permission denied
DEPLOY_SSH_KEYOpenSSH 私钥全文SSH 认证失败

显式配置 DEPLOY_SSH_USER，不要依赖错误的默认用户。

初始化云服务器

以下命令覆盖 Docker、镜像加速、部署目录、仓库与运行时环境。来源：§1.3。

ssh root@<server-ip>

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh --mirror Aliyun
sudo usermod -aG docker ubuntu

sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json > /dev/null <<EOF
{
  "registry-mirrors": ["https://mirror.ccs.tencentyun.com"]
}
EOF
sudo systemctl restart docker

sudo mkdir -p /opt/yasi-words
sudo chown $USER:$USER /opt/yasi-words
cd /opt/yasi-words
git clone https://github.com/<owner>/<repo>.git .

用随机值创建服务器端 .env，并确保该文件被 Git 忽略：

cat > .env <<EOF
POSTGRES_USER=yasi
POSTGRES_PASSWORD=$(openssl rand -base64 24 | tr -d '/+=' | head -c 24)
POSTGRES_DB=yasi_db
ADMIN_PASSWORD=$(openssl rand -base64 24 | tr -d '/+=' | head -c 24)
SESSION_SECRET=$(openssl rand -base64 48)
APP_PORT=3000
TZ=Asia/Shanghai
AUDIO_BUNDLE_URL=https://github.com/<owner>/<repo>/releases/download/<tag>/audio.tgz
EOF

grep -E "^\.env$" .gitignore || printf '%s\n' '.env' >> .gitignore
exit
ssh ubuntu@<server-ip> "docker --version && docker compose version"

生成部署 SSH keypair

密钥必须在本地生成，公钥进入服务器，私钥进入 GitHub Secret。来源：§1.4。

ssh-keygen -t ed25519 -C "github-deploy-yasi" -f ~/.ssh/yasi_deploy
ssh-copy-id -i ~/.ssh/yasi_deploy.pub ubuntu@<server-ip>
ssh -i ~/.ssh/yasi_deploy ubuntu@<server-ip> "echo OK"
cat ~/.ssh/yasi_deploy
  • 把 yasi_deploy.pub 加入服务器 authorized_keys。
  • 把私钥完整内容写入 DEPLOY_SSH_KEY，包括 BEGIN 与 END 行。
  • 先在本地验证免密登录，再让 GitHub Actions 使用同一把密钥。

处理 PostgreSQL volume 密码陷阱

PostgreSQL volume 会保留首次 initdb 的密码。以后只修改 .env 不会同步数据库角色密码，应用会报 password authentication failed。来源：§1.5。 

cd /opt/yasi-words
docker compose up -d postgres
docker compose logs postgres | grep -E "PASSWORD|initdb" | head -5

docker compose exec postgres env PGPASSWORD=<masked> psql -U yasi -d yasi_db \
  -c "ALTER USER yasi WITH PASSWORD '<new-postgres-password>'"

docker compose up -d
docker compose ps
curl http://localhost:3000/login
安全做法：不要把旧密码或新密码写进教程、终端历史、日志或 Git。上面的值全部是占位符。

首次验证只需要 SSH 与应用端口。生产环境应由 nginx 终止 TLS，并减少直接暴露。来源：§1.6。
