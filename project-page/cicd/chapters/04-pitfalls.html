ACR（阿里云容器镜像）

坑 1 · ACR 用户名 ≠ 阿里云账号

症状
unauthorized: authentication required。
原因
把阿里云账号密码当 ACR 密码。
修法
ACR 个人版 → 「访问凭证」→ 重置密码；用户名为账号全名（不是邮箱或昵称）。

坑 2 · cache-to 推 cacheconfig.v0 被 ACR 拒

症状
denied: unknown manifest class for application/vnd.buildkit.cacheconfig.v0。
原因
cache-to: type=registry 写 BuildKit cache 当 OCI artifact，ACR 不认这个 media type。
修法
改 cache-to: type=inline：cache 嵌进 image（OCI 标准，ACR 接收）。

Docker / 镜像构建

坑 3 · 阿里云 library/postgres 镜像路径不通

症状
pull access denied for registry.cn-hangzhou.aliyuncs.com/library/postgres。
原因
library/ 镜像加速已下线。
修法
所有 image: 和 FROM 改 docker hub 官方名 （postgres:16-alpine / node:22-alpine）， 并在 daemon.json 加 "registry-mirrors": ["https://mirror.ccs.tencentyun.com"]。

坑 4 · docker compose pull 永远是 no-op

症状
CI/CD 全绿，但 server 上代码不变。
原因
app service 只有 build: 没 image:，pull 触发 silent skip， up --force-recreate 直接在 server 上重新 build。
修法
docker-compose.yml 加 image: ${APP_IMAGE:-}，让 APP_IMAGE 环境变量在 deploy 时指向 ACR tag。

坑 5 · BuildKit 拒绝 shell redirect

症状
'/2>/dev/null': not found。
原因
COPY --from=builder /app/public ./public 2>/dev/null || true： BuildKit 严格 validator 不允许在 COPY 里写 shell 重定向。
修法
删 2>/dev/null || true；builder 阶段加 RUN mkdir -p /app/public 确保目录存在。

坑 8 · Audio bundle 在 build 时拉不到

症状
所有 /audio/*.mp3 404。
原因
GitHub Actions runner 上 curl https://github.com/.../audio.tgz 失败 （5 分钟超时），image 里 audio 目录为空。
修法
docker-compose.yml 加 audio_data named volume 持久化； entrypoint.sh 在 audio 目录为空且 AUDIO_BUNDLE_URL 非空时 runtime fetch。

坑 12 · /favicon.ico 404

症状
浏览器 console noise，无功能影响。
原因
Next.js 没自动从 public/ 拾取 favicon。
修法
src/app/icon.png 放 32×32 PNG，Next.js 自动作为 favicon。

坑 16 · Server 磁盘被旧 docker image 填满

症状
deploy 看起来成功，但 fix-prod-schema.yml 第一步 git fetch 报 fatal: write error: No space left on device。
原因
每次 deploy GH Actions push 3 个 tag（latest + short_sha + timestamp），旧的 timestamp tag 永远占着不释放。
修法
跑 Free-Disk workflow；或 deploy.yml 自带 prune 逻辑 （保留当前 + 1 个最近非当前 image）。

GitHub Actions workflow

坑 9 · DEPLOY_SSH_USER 漏配默认 root

症状
Permission denied (publickey)。
原因
username: ${{ secrets.DEPLOY_SSH_USER || 'root' }} 漏配时 fallback 到 root，但你的密钥只给了 ubuntu。
修法
必须显式加 DEPLOY_SSH_USER=ubuntu secret。

坑 10 · args: 块只有注释被 strict validator 拒绝

症状
services.app.build.args must be a mapping。
原因
YAML 解析空 mapping 失败（注释不算 key）。
修法
要么放真 key-value（AUDIO_BUNDLE_URL: ${AUDIO_BUNDLE_URL:-}）， 要么显式写 args: {}。

坑 11 · /opt/yasi-words 路径硬编码

症状
项目 clone 在 ~/projects/...，workflow 里 cd /opt/yasi-words 失败。
原因
路径没参数化。
修法
固定 /opt/yasi-words，server 初始化时 sudo mkdir -p； 未来可改成 secret。

坑 17 · deploy.yml 只 pull image，不更新 server host 上的 scripts/

症状
Fix-Prod-Schema workflow 报 scripts/fix-prod-schema.sql: No such file or directory， 即使文件已 commit 到 main。
原因
deploy.yml 只 docker pull + up -d，不更新 server host 上的 /opt/yasi-words/scripts/（是初始 git clone 创建的工作树，不是 image 内容）。
修法
所有需要 server-side host 文件的 workflow 第一步必须 git fetch + git reset --hard origin/main。

数据库（Postgres + Prisma）

坑 7 · Postgres volume 不随 .env 同步密码

症状
password authentication failed for user "yasi"。
原因
volume 持久化的是首次 initdb 时的密码，.env 改了不自动同步。
修法
用旧密码连进 postgres，ALTER USER yasi WITH PASSWORD '<.env 里的密码>'。 详见 CICD.md §1.5。

坑 13 · prisma db push 在已有数据的表上加 NOT NULL 列失败，整个 push rollback

症状
上线多用户系统后生产 admin 登录报 500；docker logs yasi-app 显示 PrismaClientKnownRequestError: The table 'public.User' does not exist in the current database.
原因
Prisma 在 PostgreSQL 上的 db push 是单一事务。当 schema 改动同时包含「给已有数据的表加 userId Int NOT NULL」+「创建新表 User / Invitation」， PostgreSQL 拒绝给已存在的表加 NOT NULL 列无 default value → 中间步骤失败 → 整个事务 rollback → 新表也回滚。
修法
  1. 首次 schema 加 userId 列必须带 default value（如 userId Int @default(0)），然后迁移脚本改成真值。
  2. entrypoint 失败时 loud-exit（去掉 || true），让 push 错误直接 fail container。
  3. 建立 production schema recovery（scripts/fix-prod-schema.sql + Fix-Prod-Schema workflow）。
  4. 事后 reset 流程（Reset-Admin-Password workflow）绕过 entrypoint 直接修 admin 密码。

Shell 调用 docker 的细节

坑 6 · Cookie Secure flag 在 HTTP 部署被 drop

症状
登录后 URL 仍是 /login?next=%2F，前端无报错。
原因
secure: process.env.NODE_ENV === "production" 让 cookie 带 Secure 标志， HTTP 下浏览器不存。
修法
改为 secure: process.env.AUTH_COOKIE_SECURE === "true"（HTTPS 时显式开）。 HTTPS 部署时 .env 加 AUTH_COOKIE_SECURE=true。

坑 14 · docker exec psql -f /host/path 找不到文件

症状
psql: error: /opt/yasi-words/scripts/fix-prod-schema.sql: No such file or directory， 但 ls -la 显示文件就在 server host 上。
原因
docker exec 在 container 内部执行 psql，-f /opt/yasi-words/... 是 host 路径，但 psql 在 container 里只能看到自己的文件系统。
修法
用 stdin 把 host 文件喂进 container： 
# 错: psql 在 container 里看不到 host 路径
docker exec -i yasi-postgres psql ... -f /opt/yasi-words/scripts/fix.sql

# 对: stdin 把文件内容 pipe 进去
docker exec -i yasi-postgres psql ... < /opt/yasi-words/scripts/fix.sql

坑 15 · docker exec -e 不继承宿主 env，必须显式传

症状
Reset-Admin-Password workflow 报 password too short， 但 input 明明传了 8 位密码。
原因
bash 脚本里的 NEW_PW="$X" 是宿主 shell 变量，不会自动传入 docker exec 启动的 container。
修法
所有要传给 container 的 env 必须出现在 docker exec -e 后： 
# 错: NEW_PW 是宿主变量，container 看不到
NEW_PW="Admin@2026" docker exec -i yasi-app node -e "..."

# 对
docker exec -i -e NEW_PW="Admin@2026" yasi-app node -e "..."
