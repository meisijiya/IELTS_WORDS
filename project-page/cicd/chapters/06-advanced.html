HTTPS / Nginx 反代

不要让 3000 端口直接暴露公网。nginx 终结 TLS，再反向代理到 app 容器： 

# /etc/nginx/sites-available/yasi-words
server {
  server_name words.example.com;

  location / {
    proxy_pass http://localhost:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}

HTTPS 部署下，.env 加 AUTH_COOKIE_SECURE=true 恢复 secure cookie（详见 坑 6）。

私有 ACR 镜像代理

国内拉 docker.io 慢，可以把基础镜像同步到 ACR private： 

docker pull postgres:16-alpine
docker tag postgres:16-alpine $ALIYUN_REGISTRY/meisijiya/postgres:16-alpine
docker push $ALIYUN_REGISTRY/meisijiya/postgres:16-alpine

然后 docker-compose.yml 和 Dockerfile 都用 ACR 地址。 省掉 daemon.json 里 registry-mirrors 的折腾，但私有 ACR 自身要走 内网或公网认证 pull。

Self-hosted runner

GitHub-hosted runner 国内访问部分 ACR / GitHub Release 不稳。把 runner 装到云服务器上： 

# GitHub → Settings → Actions → Runners → New self-hosted runner
# 跟着步骤在服务器跑一遍
./config.sh --url https://github.com/<owner>/<repo> --token <TOKEN>

# 然后改 workflow
runs-on: self-hosted
取舍：self-hosted runner build 快（无 5-6 分钟 build），但 server 需要 24h 在线 + 公网可被 GH 控制面访问。如果只是想省 build 时间，建议保留 GH-hosted runner + cache 关闭的方案。

多实例部署

docker-compose.yml 加 deploy.replicas: 3，nginx upstream 做 LB。横向扩到 2-3 实例足够个人项目用。

注意：多实例下 Postgres 仍是单点；如需 HA，迁移到云厂商托管 PG（如 阿里云 RDS），让 DATABASE_URL 指向托管实例即可。
